# astra-design-review（專案級 Skill 草案 v0.1）

狀態：**草案**，未經擁有者確認。只做審查，不修改任何檔案；發現問題輸出 findings，由原作者修正後再審。

## 前置
- 你必須沒有參與這個畫面的設計或實作。
- 證據是截圖：`acceptance/screens/draupnir-v21/round*/{route}-{dark|light}[-mobile].png`。必須實際用圖片讀取工具看圖，不得只看 axe 報告。

## 檢查表（每個畫面，深/淺 × 桌面/行動）
1. **排版**：字級是否 ≥ 14px；標題層級；有沒有一字一行、截斷、重疊、錯位、未套樣式的元素。
2. **版面與密度**：第一眼是否是任務；空間分配；是否過度依賴細分隔線與純文字列表；元件是否一致。
3. **色彩與對比**：兩個主題皆需 WCAG AA；不得只靠顏色表達狀態；沒有米黃暖色後台或大面積色塊。
4. **互動**：每個按鈕是否有實際功能；四態是否齊全；對話框、焦點、鍵盤。
5. **資料誠實**：匯入快照有來源與絕對時間、沒有「即時」暗示；未確認執行者；測試資料徽章；Human Gate 缺證據無核准捷徑；本機決定標明未同步 Supervisor；未驗證整合有標示。
6. **禁則**：星空、粒子、霓虹、發光、大漸層、相同卡片陣列、emoji 圖示、KPI 英雄區、無功能裝飾。
7. **行動版**：390px 無水平捲動，表格可用。

## 輸出
`DESIGN-REVIEW-<範圍>.md`：每個 finding 必須有 (a) 截圖檔名、(b) 看到什麼、(c) 嚴重度 blocker/major/minor、(d) 規範條款。最後給「是否可驗收」與未能檢查的範圍。不要依賴作者的說明。
